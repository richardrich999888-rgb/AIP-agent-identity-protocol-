## Security review scope

README, available SECURITY files, license files and selected native integration sources were read at the recorded pins. A SECURITY reporting policy alone is not a complete security model or an independent audit. Missing root SECURITY files are not evidence of an insecure project. The lock records exactly which source files were read. Complete deployment threat models, transitive vulnerability assessment, binary provenance verification and clean-host tests remain open.

## Standards and identity proposals

[RFC 8693](https://www.rfc-editor.org/rfc/rfc8693) specifies OAuth token exchange; delegation and impersonation must not be conflated. [RFC 9449](https://www.rfc-editor.org/rfc/rfc9449) defines DPoP; ordinary bearer authentication does not supply it. Neither profile is implemented by silently accepting a cnf claim.

[draft-fane-opena2a-aip-02](https://datatracker.ietf.org/doc/html/draft-fane-opena2a-aip-02) is an individual Internet-Draft, not an IETF-approved standard. [draft-aip-agent-identity-protocol-00](https://datatracker.ietf.org/doc/draft-aip-agent-identity-protocol/) is another separate proposal (expired at this inspection). OpenA2A AIP and VANIAN AIP remain distinct. No identity equivalence or trust-score conversion is asserted.
