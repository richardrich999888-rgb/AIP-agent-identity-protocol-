# Recording the SYNTRIASS demo video, step by step

**For:** Anuj. **Goal:** one honest 3-minute demo video, plus one short video per
demo, recorded from the live software, with your own voice-over.

**Two rules that are not negotiable:**
- Every result on screen comes from a live run.
- Nobody's voice or face is generated by AI. The voice-over is a real person.

---

## 1. Where everything is

Two repositories, both on the branch **`feature/wow-demos`**. Clone them side by
side in the same folder, because the demos look for `../overlay`:

```sh
mkdir ~/syntriass && cd ~/syntriass
git clone -b feature/wow-demos https://github.com/richardrich999888-rgb/AIP-agent-identity-protocol-.git aip
git clone -b feature/wow-demos https://github.com/richardrich999888-rgb/overlay.git overlay
```

| What | Path |
|---|---|

## 2. The recording machine (one-time setup, about 1 hour)

You need a Linux laptop or desktop with these, ideally plugged in:
- Ubuntu 22.04 or 24.04
- root access
- about 15 GB free disk
- 8 GB RAM or more
- internet for the setup only

```sh
sudo apt update
sudo apt install -y build-essential cmake git curl python3 python3-venv \
     docker.io auditd netcat-openbsd openssl libc6-dev
curl https://sh.rustup.rs -sSf | sh -s -- -y && source ~/.cargo/env
```

**Build the binaries:**

```sh
cd ~/syntriass/aip
cargo build --release --locked -p aip-probe -p aip-collector -p aip-observe-verify -p syntriass-runtime
bash deploy/syntriass/setup_env.sh                 # pinned Python environment for the runtime
cd ~/syntriass/overlay
cargo build --release --locked --lib
cargo build --release --locked --bin syntriass-identity
cargo build --release --locked --features cbom,compliance --bin syntriass-cbom
```

**Build `llama-server`**, the local model server. Use the same source as the
benchmark (details in `demos/models/README.md`):

```sh
mkdir -p ~/syntriass/llama && cd ~/syntriass/llama
curl -LO https://files.pythonhosted.org/packages/e4/b4/c8cd17629ced0b9644a71d399a91145aedef109c0333443bef015e45b704/llama_cpp_python-0.3.16.tar.gz
sha256sum llama_cpp_python-0.3.16.tar.gz           # must be 34ed0f9bd9431af045bb63d9324ae620ad0536653740e9bb163a2e1fcb973be6
tar xzf llama_cpp_python-0.3.16.tar.gz
cmake -S llama_cpp_python-0.3.16/vendor/llama.cpp -B build -DCMAKE_BUILD_TYPE=Release -DGGML_NATIVE=ON -DLLAMA_CURL=OFF
cmake --build build --target llama-server -j
```

**Download the models.** About 4.5 GB. Every file's hash and licence is
checked; anything wrong is refused:

```sh
cd ~/syntriass/aip
python3 demos/models/stage.py ~/syntriass/bundle --llama-server ~/syntriass/llama/build/bin/llama-server
```

**Check everything:**

```sh
sudo SYNTRIASS_BUNDLE=$HOME/syntriass/bundle python3 demos/launch.py check
```

Every line you plan to record must say `READY`. If one says `NOT READY`, the
reason printed beside it says exactly what to fix.

## 3. Before you press record

1. Rehearse each demo once with the camera off:
   `sudo SYNTRIASS_BUNDLE=$HOME/syntriass/bundle python3 demos/launch.py run investor-3min`.
   It should end with `PASS`.
2. Start the console:
   `sudo SYNTRIASS_BUNDLE=$HOME/syntriass/bundle demos/console/start.sh`,
   then open **http://127.0.0.1:8770/** in Chrome or Firefox.
3. Set up the screen:
   - Set the display to **1920×1080** and browser zoom to **110%**.
   - Hide bookmarks and close other tabs.
   - Turn on Do Not Disturb.
4. Set up the voice:
   - Use a USB or headset microphone, not the laptop's built-in one.
   - Record in a quiet room with soft furnishings.
5. Install the recorder, **OBS Studio** (free):
   - Make a **Display Capture** or **Window Capture** of the browser.
   - Settings → Output → Recording format: **MP4**.
   - Settings → Video: **1920×1080, 30 fps**.
   - Add the microphone source and keep its level peaking around −12 dB.

## 4. What to record

**Video A, the 3-minute investor demo.** Record it in one take, or in four
clips with the same order:

| Clip | On screen | Action |
|---|---|---|
| A1 (0:00–0:30) | Console home page | Slowly scroll past the heading and the "ready" chips |
| A2 (0:30–1:30) | **Catch the lying agent** tab | Press **Run live** and wait about 25 s. When it finishes, scroll the three witnesses: its own log, Sniffer Dog, auditd. Then "change one byte: REJECTED" |
| A3 (1:30–2:15) | **Pull the plug** tab | Turn Wi-Fi **off** on camera. Click the sample question "vibration limit…", then **Ask offline**. Show the answer, the citations, "bytes out 0" and the cloud side failing. Then ask "What is the SCADA maintenance account password?" and show it **withheld** |
| A4 (2:15–2:45) | **Quantum X-ray** tab | Press **Run live** (about 2 s). Show the planted-vs-found table, then scroll the report |
| A5 (2:45–3:00) | Console home or logo | Closing line |

**Videos B–E, one per demo**, 1–2 minutes each: the same tabs, plus the
**Post-quantum switch** tab (press Run live and wait about 35 s) and the
**Taught-capability benchmark** tab. The benchmark tab is recorded data and
already says RECORDED. Say so in the voice-over too.

While waiting for a live run:
- Keep recording.
- In editing, you may speed the wait up (for example 4×), but only with a
  visible "4× speed" label.
- Never cut out the waiting and present it as instant.

## 5. Voice-over

- Your words: `demos/recording/NARRATION.md` has a script per demo, line by
  line, and what each line points at on screen.
- The 3-minute script, Video A:

  > **A1:** "AI agents now act on their own, and their own logs can be wrong.
  > SYNTRIASS proves independently what an AI system actually did. Everything
  > you'll see runs live on this laptop."
  >
  > **A2:** "This is a test agent we scripted to misbehave. Its own log says it
  > only read an invoice and wrote a summary. Sniffer Dog, watching from the
  > Linux kernel, saw a hidden network connection and a file written outside
  > its workspace, tied to this exact process. A second, independent kernel
  > subsystem, auditd, saw the same. The evidence is signed with a key the
  > agent never sees. If we change a single byte, verification fails."
  >
  > **A3:** "Now we pull the plug. Wi-Fi is off. Our runtime answers from the
  > organisation's own synthetic documents, with citations, on a small local
  > model, and zero bytes leave the machine. The cloud app gets nothing. And a
  > user without clearance asking for a password gets nothing either."
  >
  > **A4:** "The next problem for the same customers is quantum computing. Quantum
  > X-ray found every planted quantum-vulnerable key, certificate and cipher on
  > this sample server, exactly where each one lives, and invented nothing."
  >
  > **A5:** "Independent proof of what AI does, deployable where the cloud
  > can't go. That's SYNTRIASS."
- Record live, talking while you click, or record the voice afterwards in a
  quiet room (OBS or Audacity) and line it up in editing. Afterwards is usually
  cleaner.
- Speak at about 140 words per minute. Pause one second after each result
  appears.
- Say **"proof of concept"** for the post-quantum switch.
- Say **"a test agent we scripted to misbehave"** for the lying agent.
- Say **"synthetic documents"** for Pull the plug.
- **Never say:** "quantum-proof", "learns by itself", "fine-tuned",
  "production-ready", "catches any AI agent", or "zero overhead".

## 6. Editing (DaVinci Resolve or Shotcut, both free)

1. Import the clips in order A1–A5 and trim dead time at the start and end of
   each clip only.
2. Lay the voice track under the clips, and adjust clip lengths to the voice,
   not the other way round.
3. **Title card (2 s):** `assets/syntriass-logo.jpg` on the navy background
   `#0A0140`.
4. **Lower-third text**, always visible for the first 5 s of each demo:
   *"Recorded live on <date>, <laptop model>. Commit <AIP short hash> /
   <overlay short hash>"*. Take the hashes from the chips on the console home
   page.
5. Label any speed-up with on-screen text, for example "4× speed".
6. Add captions: auto-generate, then correct them by hand. Check the product
   names: SYNTRIASS, Sniffer Dog, auditd, ML-KEM.
7. Music: none, or very quiet royalty-free music under the intro only. Keep the
   voice dominant.
8. **Export:** MP4 (H.264), 1920×1080, 30 fps, about 12 Mbit/s, AAC 192 kbit/s
   audio. Name it `syntriass-demo-<date>-3min.mp4`.

**Final check before sharing:**
- Every number spoken also appears on screen.
- No result was edited, re-typed or re-ordered.
- The RECORDED label is visible on the benchmark part.
- The lower-third shows the date and commits.

---

## 7. If something goes wrong on camera

- **A run shows FAIL:** don't edit it into a pass. Stop, run
  `python3 demos/launch.py check`, fix what it names, and record that clip
  again.
- **Pull the plug says NOT READY:** `SYNTRIASS_BUNDLE` is missing from the
  `sudo` command.
- **Security says "auditd is not running":** run `sudo auditd && sudo auditctl -e 1`.
- **PQ or Quantum says "docker daemon not running":** run
  `sudo systemctl start docker`.
- **Anything else:** the console prints the reason in red. Send that text and
  the result file path it shows.
