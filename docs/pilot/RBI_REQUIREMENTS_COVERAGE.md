# RBI ecosystem requirements → coverage matrix

> **Status: normative for the roadmap, September 2026.** Every requirement an
> agent deployment inside an RBI-regulated entity must meet, drawn from
> `RBI_AGENT_RISK_MAP.md`, with one of four dispositions:
>
> - **EXISTS** — code and a test that exercises it, named.
> - **BUILD** — inside the accountability domain; roadmap item and acceptance
>   test named. Not shipped until the test passes.
> - **INTEGRATE** — the RE's or a partner's system supplies it; we supply the
>   evidence it consumes or the interface it calls.
> - **OUT OF SCOPE** — a different discipline with a named owner. Claiming it
>   would be false and RBI would find it.
>
> "Every solution the ecosystem requires" is honest only in this form: the
> accountability and evidence domain covered completely, and everything else
> attributed to its owner. A vendor that claims all four columns as EXISTS is
> the vendor RBI's own FREE-AI report warns REs about.

### B. Independent observation (what actually executed)

| # | Requirement | Instrument | Disposition | Where / acceptance |
|---|---|---|---|---|
| B1 | Execution observed from the kernel, not from the agent | IT Governance audit trail; FREE-AI | EXISTS | perf tracepoints + connector, `aip-observe`; `ghost-demo/tests/live_*` |
| B2 | Process identity by content hash and instance, not PID or path | IT Governance forensics | EXISTS | `ExecutionBinding`; `live.rs` scenario D |
| B3 | Container / namespace identity in the binding | same | EXISTS in the binding; **BUILD** on the observer side | `ExecutionBinding` v2 carries `ContainerIdentity` (pid/mnt/net namespace inodes as identity; cgroup v2 id as recorded context, since a cgroup-v1 host has none and a cgroup move is not a change of workload). `compare_execution` distinguishes *different container* from *one side did not record one*, so a blind collector cannot manufacture a divergence. `aip-core` reads the namespaces from `/proc/<pid>/ns/*`. | B4 | Evidence key off the observed host | IT Outsourcing; CERT-In evidence integrity | EXISTS | `aip-collector` wrapped custodian; `tests/e2e.rs` |
| B5 | Blinded observer says so, never "nothing happened" | FREE-AI safety; non-repudiation | EXISTS | `IntegrityUnknown` across the split; ledger OI-01..OI-12 |
| B6 | Gate-independent coverage for non-occurrence claims | non-repudiation | EXISTS in pilot | connector in `aip-probe`; `covers_process_lifecycle` |
| B7 | File and wire evidence in the pilot probe | forensics | **BUILD** | R8: fanotify + AF_PACKET in `aip-probe` with capability trimming; live tests mirror `ghost-demo` |
| B8 | No payload capture, ever | DPDP data minimisation | EXISTS (invariant I23) | `wiretap.rs` header-only decoder; grep-clean of payload capture |
| B9 | Confidential probe→collector link | IT Governance; DPDP | **DONE** | `aip_transport::confidential`: a `Noise_NK_25519_ChaChaPoly_SHA256` session the authenticated protocol runs *inside*. The probe pins the collector's static public key; the collector's key is a third key, distinct from its evidence key and from any probe's transport-auth key, and a loaded key file is proven to be a pair before use. Both daemons use it unconditionally — there is no plaintext mode in either. **The acceptance test is a capture:** a tap on the probe's socket records the session, and the recording contains neither the probe id, nor its transport key in any encoding, nor a wire field name, nor the batch; a plaintext control finds all of them, which is what makes the negative result worth anything. A wrong pinned key fails the handshake before any authentication; a tampered message fails its tag and poisons the stream; a 4 MiB payload crosses ~65 messages intact; two sessions never share ciphertext. No `ring`, no TLS stack: `snow` on the curve25519/ChaCha20-Poly1305/SHA-256 primitives the workspace already carries |

### D. Evidence integrity, portability and verification

| # | Requirement | Instrument | Disposition | Where / acceptance |
|---|---|---|---|---|
| D1 | Every artefact signed, domain-separated, canonically encoded | non-repudiation | EXISTS | `aip-types::canonical`; Gate-13 distinct-domain test |
| D2 | Append-only commitment with inclusion and consistency proofs | IT Governance; CERT-In | EXISTS | `aip-nexora` Merkle log, signed heads |
| D3 | External anchoring of log heads | tamper evidence against the operator | **DONE** (mechanism) / INTEGRATE (placement) | `aip-standalone/aip-anchor` and the `aip-anchor` command. | D6 | Release artefacts **signed**, not only checksummed | supply-chain assurance; MRM third-party | EXISTS | R12: keyless Sigstore signing in `release.yml`, with the release job verifying the signature it just produced under the same identity constraints a downloader uses, so a misconfiguration fails the release rather than shipping an unverifiable artefact. `VERIFYING.md` ships with the release. No long-lived signing key exists to leak. Note: the published key |
| D7 | Storage-enforced immutability and retention (WORM, RLS, 180-day floor) | CERT-In 180 days; IT Governance | EXISTS (controls) / **BUILD** (backup) | `deploy/sql/hardening.sql`, applied by the owning role: the service's role holds SELECT and INSERT only, and triggers make evidence append-only and enforce legal hold **against the owner too**. Row-level security scopes an unfiltered query and admits nothing to a connection that declared no tenant. Retention floor of 180 days is a CHECK, so a misconfigured policy is refused at write time. ### E. Operations and incident handling

| # | Requirement | Instrument | Disposition | Where / acceptance |
|---|---|---|---|---|
| E1 | Incident evidence bundle producible in minutes | CERT-In 6 hours; FREE-AI incident form | **DONE** | `aip-standalone/aip-incident` and its `aip-incident` command: `export --agent --from --to` assembles one signed bundle from already-signed documents (attested batches, verdicts, access ledgers, sensor health, expectations) and **computes the coverage it does not have**. Gaps are derived by subtracting the intervals the enclosed batches claim from the window asked for, they sit inside the manifest signature, and `verify` recomputes them independently. Reads only files — no collector or service call, so a network fault at the wrong moment cannot stop a filing. **Open:** the six-hour *reporting* path itself (who files, to whom, on which form) is the entity's, not the supplier's |
| E2 | Metrics, SIEM export, runbook | IT Governance; SOC | **DONE** | `GET /metrics` on the service in Prometheus text format — authenticated, and **aggregate only**: no tenant, agent or document label, because a labelled series on a shared scrape is a cross-tenant disclosure channel. `aip-standalone/aip-siem` renders a verified verdict as CEF over RFC 5424 syslog. `deploy/pilot/RUNBOOK.md` is the on-call procedure, including the CERT-In six-hour assembly and the rule that `CANNOT_PROVE` is not a clean result. **Decision:** the Prometheus exposition format rather than the OpenTelemetry SDK — every stack named in the requirement scrapes it, including the OTel Collector, and it adds no dependency to a service whose metrics surface is ten counters |
| E3 | Kill-switch trigger interface | MRM kill switch | EXISTS (tier) / **INTEGRATE** (trigger) | Enforcement tier in tree: `aip-enforce` (seccomp user-notify execve gate deciding under a signed `CapabilityEpoch`; ADR-015) and `aip-interlock` (dead-man heartbeat, actuator watchdog, measured stopping budget). Both fail closed when the epoch or heartbeat lapses and neither reads observation or reconciliation. The *trigger* from a verdict to an epoch revocation is the RE's orchestration or SOAR; containment stays advisory in pilot. |
| E4 | Clock discipline (NTP), time anchoring of evidence | CERT-In | EXISTS partly | `BootClockAnchor` per batch; INTEGRATE: host NTP to NIC/NPL servers per CERT-In |
| E5 | Backup, DR, BCP for the evidence store | IT Governance BCP | **DONE** (drill) / entity's (RPO/RTO, off-site, cadence) | `deploy/sql/restore_drill.sh`: an **exercised** restore against a real PostgreSQL. It dumps a hardened vault, restores into a separate empty cluster, and verifies both the evidence (byte-identical, verbatim signed bytes) **and that every control survived** — append-only trigger, legal hold, 180-day retention floor, least-privilege `aip_app` grant, and tenant row-level security all still enforced. The half a naive drill skips is exactly step 5. `docs/BACKUP_AND_RECOVERY.md` states what the entity sets: RPO/RTO, off-site and off-host custody, backup encryption and immutability, and the restore-drill cadence. Verified passing on Linux 6.18.44 |
| E6 | TLS and rate limiting at the service ingress | IT Governance | **DONE** | The split is by what each layer can see. **In-process** (`aip_service::ingress`, wired in `main`): a request body cap (`413` above `AIP_MAX_BODY_BYTES`, default 1 MiB), a per-request timeout (`408` above `AIP_REQUEST_TIMEOUT_SECS`, default 30 s), and a global in-flight cap (`AIP_MAX_IN_FLIGHT`, default 256). A malformed limit fails the start rather than disabling the control. **At the proxy** (`deploy/docker/reverse-proxy.conf`, referenced from compose): TLS termination, per-client rate and connection limits, and slow-loris timeouts — all needing the client's connection and address, which the service behind the proxy does not have. Tests: `aip-service/tests/ingress_limits.rs` (4) and `ingress` unit tests (4), including that an oversized body is `413` with a key and that an unauthenticated giant body is refused without being read |
| E7 | KMS/HSM custody for signing keys | IT Governance key management | **DONE** (mechanism) / entity's (module, PIN custody, ceremony) | `aip-standalone/aip-hsm`: a PKCS#11 `Custodian`. The key is generated inside the module as `CKA_SENSITIVE`, non-extractable, and there is no import path. At open the custodian reads the policy back from the module and refuses an extractable or non-sensitive key, refuses two keys under one label, and proves the pair with a probe signature. The nonce comes from the module's RNG. The envelope is byte-identical to the software signer's, so no verifier changes. Tested against SoftHSM2 through the real PKCS#11 interface, including a second PIN-holding session asking for the private key and not getting it. CI installs SoftHSM2; the tests fail rather than skip without it. `deploy/pilot/HSM_CUSTODY.md` states what the entity decides: which module, who holds the PIN, key ceremony, and key backup (open, E5) |
