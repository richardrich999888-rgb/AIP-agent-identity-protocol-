# Invention log

Recording rule: an entry is a *candidate*, never a claim. Independent
implementation does not establish novelty; prior art is listed first.

## IL-001 — Policy-variable extraction instead of decision prediction (status: supported on synthetic data, iteration 1)

- **Problem:** typed decision models (Jev, Kev) predict the decision directly,
  so the policy (thresholds, orderings) is learned approximately. That is
  wrong whenever the policy is exact, versioned and must be auditable.
- **Prior art:** semantic parsing and slot filling; neuro-symbolic program
  induction; tool-use/function-calling, where an LLM emits arguments that code
  evaluates; Jev documentation advising arithmetic in application code. The
  general idea is **not new**.
- **Mechanism under consideration:** the model emits a *distribution over the
  policy's input variables* (entity, quantity, value bucket relative to the
  policy's own thresholds). The exact policy is evaluated over that
  distribution, giving a decision distribution whose uncertainty comes only
  from interpretation. The policy is signed and versioned separately from
  the model.
- **Possible distinguishing element (unverified):** propagating
  interpretation uncertainty *through* a signed deterministic policy to a
  calibrated decision distribution, with the policy version and evidence bound
  into an AIP-authorized action record. A prior-art search has not been done;
  no patentability conclusion is possible.
- **Evidence (iteration 1, REPORT_ITER1.md):** same Qwen2.5-1.5B weights on
  300 paraphrased reports — asked for the decision: 0.343; asked only for
  (quantity, value) with the SOP applied exactly: **0.977 [0.957, 0.993]**.
  Rules → LLM-extraction cascade beats rules → TF-IDF by +0.073 [+0.037,
  +0.113] (paired). Uncertainty propagation through the policy was attempted
  via logprobs but the llama.cpp build's letter logprobs were unreliable, so
  the propagated-distribution variant is **untested**.
- **Alternative explanation:** the rule baseline's perfect score is an
  artefact of a synthetic dataset whose labels come from the same rule table.
  Real operator text will be messier; this must be tested on data not
  generated by the rule table.
- **Limitations:** needs a policy that can be stated as variables and
  thresholds; does not cover open-ended judgements.

Do not publish or disclose IL-001 externally without authorization.
