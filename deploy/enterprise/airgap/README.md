# Restricted-network and air-gapped installation

Build the Linux archive in `../linux/README.md` on an approved connected build
host. Record the clean source commit, Rust toolchain, target, OS/libc, full
successful build log and package SHA-256. Transport the archive, reviewed
installer, public release approvals and public auditor binaries through the
institution's approved transfer procedure. Never bundle signing secrets,
passphrases, tenant API credentials or customer evidence in the software kit.

The runtime tar contains the existing daemons and observer verifier, so the
destination requires no Cargo registry or Python package downloads. It still
requires installed Python 3.9+, systemd and compatible system libraries.
Obtain those OS packages from the institution's own signed offline repository.
Check ELF dynamic dependencies on the build host with `readelf` and test on
the exact destination OS. No vendored OS or system-library bundle is supplied
or validated by this directory.

If the institution rebuilds from source, prefetch the locked Rust dependency
set with `cargo vendor --locked` and configure Cargo's vendored source on the
connected build host, then prove `cargo build --offline --locked` in an isolated
clean build before approving transfer. That dependency bundle is a separate
build artifact and is **not generated by this package script**. Retain the
lockfile and third-party notices alongside its institution-generated SBOM.

Verify the archive with an independently approved hash before executing any
installer from it. A checksum that arrives only on the same untrusted medium
does not authenticate a package. Use the institution's signed release
approval when required; these new runtime archives are not published by the
repository's Sigstore release workflow yet.

Keys are generated separately on their respective hosts. Provision internal
clock sources; an isolated but undisciplined collector clock is refused.
Restrict probe egress to the collector's confidential transport endpoint and
approved time/DNS services. The observer needs no external VANIAN service,
SDK, model provider or MCP evidence server. Firewall policy is an
institution deployment step, not an automatic installer action.

Use the offline observer verifier with the public anchor agreed independently
by the auditor. Upgrade by the same approved-transfer and maintenance-window
procedure as Linux installation. Keep old public trust anchors for historical
evidence; do not roll back state to make a new collector start.
