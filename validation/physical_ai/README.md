# `physical_ai/` — the path from agent validation to physical accountability

This tree holds the tooling, scenarios and adapters for the Skill 25 validation
roadmap:

```
AI agents → robotics → physical robots → UAS → industrial autonomy
```

It extends `../` rather than replacing it. `../README.md` covers the Linux
runtime observers and `../robotics/STATUS.md` records why no robotics runtime is
installed here; this directory adds the physical-observation, UAS and industrial
layers and the adapter that keeps all of them outside the trust boundary.

## The rule the whole tree exists to enforce

> **The actor must not control the evidence used to judge the actor.**

ROS 2, Gazebo, `ros2_control`, Nav2, MoveIt 2, `rosbag2`, `ros2_tracing`,
OpenCV, AprilTag, PX4, MAVLink, MAVSDK, OPC UA and 4diac are **test subjects,
environments, telemetry sources and reference observers**. None of them is a
Vanian trust anchor. None of them is automatically independent proof.

That is enforced mechanically, not by convention:

| enforcement | where |
|---|---|
| no external framework is a production dependency | none is a workspace member; `LICENSES.md` column `Production dep?` is `NO` for all twenty |
| the adapter itself links no framework | `adapters/.../tests/no_second_hierarchy.rs::the_adapter_names_no_external_framework_type` |
| independence cannot be asserted, only derived | `ExternalObservation::is_independent` reads the provenance class; there is no settable field, and a guard test counts the assignments |
| no source reaches a physical-effect claim | `ProvenanceClass::can_support_physical_effect()` is computed and false for all eight |
| agreement never raises a ceiling | `SourceAgreement::ceiling_after_agreement` returns the base, for any count |
| the three absences stay distinct | `ObserverPosture` has four states; no observation, no observer, and unknown integrity are three different refusals |

## What runs here, and what does not

Run `./preflight.sh`. As of this writing it reports **PARTIAL**: 8 ready, 2
partial, 18 blocked.

**Runs:**

- the external fiducial observer, over **synthetic scenes only**;
- the admission adapter, over recorded traces, offline and deterministically;
- the adapter's own suite: 66 tests, and 11 mutations, all killed.

**Does not run**, with the reason:

- ROS 2, Gazebo, `ros2_control`, Nav2, MoveIt 2, `rosbag2`, `ros2_tracing` —
  `packages.ros.org` returns HTTP 403 and the Docker daemon is unreachable;
- PX4 SITL, MAVSDK — `github.com` returns HTTP 403 for the clone;
- open62541, 4diac FORTE — same channel;
- **any physical observation** — there is no `/dev/video*` device. No software
  substitutes for a camera.

Nothing is stubbed to make a blocked tool appear present. A fabricated
environment produces fabricated telemetry, and telemetry from it would be worse
than none, because it would invite a claim.

## The synthetic run, and why its result is a refusal

`observe_fiducial.py --source synthetic` renders a scene containing an AprilTag
36h11 marker at two positions and runs the **real** OpenCV detector over it. The
detector measured 400 px of displacement, which is what was rendered.

The adapter then **refused every record**:

```
[0] PoseMeasurement  SimulatorGroundTruth -> REFUSED (SimulatorGroundTruthOfferedAsPhysical)
[1] PoseMeasurement  SimulatorGroundTruth -> REFUSED (SimulatorGroundTruthOfferedAsPhysical)
[2] Displacement     SimulatorGroundTruth -> REFUSED (SimulatorGroundTruthOfferedAsPhysical)
PHYSICAL EFFECT: NOT ESTABLISHED
```

That is the correct answer and it is the point of running it. A rendered scene
is not an observation of any world; the detector is real and the scene is not.
The run establishes that the **pipeline** works end to end and establishes
nothing about any robot.

## Modern Gazebo, not Classic

Where a Gazebo environment is provisioned it must be **Gazebo Sim** with
`gz_ros2_control`. The Gazebo Classic `ros2_control` integration is end-of-life
and current `ros2_control` guidance points to the modern one. Nothing here
depends on either; the choice is recorded so a future provisioning pass does not
have to rediscover it.

## Hardware safety

**Default: SIMULATION ONLY.**

No physical robot or UAS may be armed or moved by anything in this tree. For
UAS specifically: `ARM = DISABLED`, `TAKEOFF = DISABLED`,
`MISSION EXECUTION = DISABLED`. Enabling any of them requires an explicit,
separately authorized physical test with a safety case, a test authority and
hardware — none of which is a software decision and none of which this tree may
pre-authorise. See `uas/hitl/README.md`.

## The milestone that has not been reached

> **ONE PHYSICAL QUANTITY + EXTERNAL MECHANISM + VALID OBSERVATION PATH +
> REACHES `from_attested`.**

Until that happens, physical accountability is **unvalidated**. It is not
partially validated, not simulation-validated-therefore-nearly-there, and not
implied by any number of passing software tests.

Two things stand between here and it, and only the first is about this
environment:

1. **A camera, a robot, and a separate collector machine.** Procurement and
   provisioning.
2. **A `SourceMechanism` that carries an optical observation.**
   `ProvenanceClass::mechanism()` returns `None` for every external sensor
   class, so even a perfect camera on a separate machine reaches
   `AdmittedAsCorroboration` and stops. Closing that is an `aip-observation`
   change, constrained by ADR-003, and it is **outside Skill 25**.

The second point is the one people miss. Buying a camera does not reach the
gate.
