# Vanian AIRI — Python SDK

The Python boundary for AI-stack accountability. An agent uses this to make
**signed statements** about what it did. It does not use it to prove
anything: proof requires independent observation, which by construction
happens somewhere this process cannot reach.

## Install

```
pip install cryptography==41.0.7    # the only non-stdlib dependency
```

The canonical encoder, commitments, execution context and event construction
need no third-party package at all — `cryptography` is imported lazily and
only when a key is loaded.

## Use

```python
from vanian_airi import (
    load_agent_identity, new_execution, bind,
    AiriEmitter, FrameworkIdentity, ReportedOutcome,
)
from vanian_airi.adapters import FrameworkAdapter, ModelAdapter, ToolAdapter

identity = load_agent_identity("aip1abc...", "/run/secrets/agent.key")
emitter  = AiriEmitter(identity, FrameworkIdentity("langgraph", "0.2.0",
                                                   "vanian-airi-adapter/1"))
fw, model, tools = FrameworkAdapter(emitter), ModelAdapter(emitter), ToolAdapter(emitter)

with bind(new_execution(identity.aip_id, decision_id=expectation_id)):
    fw.on_agent_start(role="refund-bot")
    model.requested("claude-opus-5", prompt={"q": "refund?"})
    call = tools.request("http.post", "http.post", {"amount": 5})
    # ... the real call happens here ...
    tools.report(call, ReportedOutcome.SUCCESS, transport_status=200)
    fw.on_agent_end()
```

## What the events establish

That this agent said these things, in this order, about this execution, under
this authorization, and that the statements have not been altered since.

## What they do not establish

That any of it happened. The signing key is the agent's, the clock is the
agent's, and the process emitting the events is the process under scrutiny.
Occurrence is settled by `aip_airi::corroborate` against collector-signed
observation, off this host, and its default answer is `CANNOT_PROVE`.

## What this SDK deliberately cannot do

There is no `prove()`, no `set_evidence_strength()`, no `issue_warrant()`,
no `authorize()`, and no way to load an observer's private key. Each absence
is a security property and each is asserted by `tests/test_boundary.py`,
which fails if any of them is ever added.

Loading a key fails closed: a missing, unreadable, malformed or
world-readable key raises `IdentityUnavailable`. It is never regenerated —
a process that mints a replacement identity has silently become a different
principal.

## Tests

```
python3 -m unittest discover -s tests    # 50 tests
```

`tests/test_canonical_parity.py` is the load-bearing one: it checks the
Python encoder byte-for-byte against vectors generated by the Rust encoder.
Regenerate them with:

```
cd ../../aip-standalone
cargo test -p aip-airi --test parity_vectors -- --ignored --nocapture
```

The reverse direction — Rust verifying signatures the Python SDK produced —
is `aip-standalone/aip-airi/tests/python_interop.rs`.
